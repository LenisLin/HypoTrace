# STOmicsDB Round 2B Bundle Validation Protocol

## Purpose

Use this mandatory curator protocol to validate one approved STOmicsDB bundle
after Round 2A has completed. One invocation handles exactly one approved
bundle and publishes only that bundle's staged `localization.yaml` plus
necessary bundle-local `extracted/` content.

## Required Inputs

- One fixed `bundle_id`, `bundle_type`, `owner_type`, and `owner_id`.
- The approved `registry/localization_queue.jsonl` row for that bundle.
- Absolute `repository_workdir` and `nas_data_root` paths.
- One unique absolute `bundle_staging_directory`.
- The absolute canonical bundle directory.
- `expected_target_paths`, generated by the coordinator from acquisition-plan
  target paths under the approved bundle target prefix.
- The assignment-specified existing host conda environment or conda prefix.

Reject an assignment with missing values, unresolved placeholders, duplicate
bundle identity, relative filesystem paths, paths outside declared roots,
overlapping staging/canonical destinations, or a missing existing conda
environment. Also reject an assignment whose NAS-data-root-relative
`expected_target_paths` are missing, duplicated, absolute, outside the canonical
bundle `artifacts/` directory, or inconsistent with the approved bundle target
prefix.

## Required Reads

Before acting, read:

- `docs/datasets/data-contract.md`
- `docs/datasets/stomicsdb-localization-workflow.md`
- `docs/datasets/public-data-research-case-extraction.md`
- `contracts/prompts/curation/stomicsdb_round2b_bundle_validation.md`
- the approved queue row and the current canonical or staged bundle state.

## Execution Protocol

1. Reconcile existing bundle state by `bundle_id`, owner identity, queue row,
   target directory, artifact paths, and prior generation. Resume a valid
   incomplete staging generation; never overwrite a valid canonical generation
   in place.
2. Verify that every `expected_target_paths` entry resolves inside the assigned
   bundle's `artifacts/` directory and is a regular completed file.
3. Compute and record SHA-256, size, format, and role for each artifact.
4. Extract archives only when needed to enumerate or inspect approved resources.
   Write extracted content only under the same bundle's `extracted/` directory.
5. Using only the assignment-specified existing conda environment, inspect
   structural readability: H5/H5AD keys and dimensions, `obs` and `var`
   columns, coordinate columns and ranges, image dimensions, sample
   identifiers, metadata columns, and archive members.
6. Do not install packages, create environments, modify environment state, or
   substitute an unstated environment. If the assigned existing environment
   cannot read the format, return nonterminal
   `worker_status: awaiting_environment` with the
   format and error summary, publish no `localization.yaml`, and wait for the
   coordinator to retry with another already existing environment.
7. Do not run clustering, differential expression, enrichment, spatial
   statistics, reannotation, format conversion, biological interpretation, or
   paper-result reproduction.
8. Do not reconstruct approved-resource coverage from
   `registry/acquisition_plan.tsv`. Bundle membership comes from the approved
   queue row, `expected_target_paths`, and canonical bundle directory. Do not
   create or persist a coverage sidecar or `resource_ref` to TSV-row mapping.
9. Stage `localization.yaml` using the data contract's Round 2B fields. Write
   companion extracted content first and `localization.yaml` last.
10. Parse the staged YAML, verify every recorded local path is
    NAS-root-relative, verify hashes for recorded artifacts and extracted
    files, and repair actionable local failures before returning.

## Terminal States

Return `worker_status: LOCALIZED` only when every expected target path is
present, hash-recorded, and structurally readable under the allowed Round 2B
checks.

Return `worker_status: awaiting_environment` only when the expected files are
present but the assigned existing environment cannot read the format. This is
nonterminal and must not publish `localization.yaml`.

Return `worker_status: BLOCKED_EXTERNAL` only when the next required action
needs access, credentials, unavailable service, storage, an unrecoverable remote
object, or another condition outside the execution window after retryable local
causes are exhausted.

## Boundary

Do not write registries, entity manifests, case manifests, source manifests,
case data manifests, task packages, HVUs, dual-chain output, audit reports, or
scientific findings. Do not create case IDs or assign `DATA_READY`.
